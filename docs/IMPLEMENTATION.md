## Ontology, authorization and transaction

`config/ontology.json` supplies versioned Store/Lot/InventoryPosition types, links and typed SetIsolation. `src/contracts.mjs` validates exact types, finite eq/in/and queries, bounded traversal and compatibility. Kernel operations include get/query/search/traverse/history, validate/submit/status/approve, draft/diff/editCases/review/publish/compatible rollback, ingest/sourceStatus/observe and allowlisted tool proposals. Pages are bounded at 100, scan/traversal at 1000, depth at two. Query snapshots bind principal/delegation, scope, columns, policy epoch and Ontology version. Counts and snippets derive only from authorized data.

The loopback `POST /rpc` gateway binds opaque sessions and registered delegation headers to actor/onBehalfOf, rejects self-reported identities and verifies tenant. Kernel transactions repeat authorization. Actor, subject and delegation operation/store scopes intersect; session/identity/delegation expiry or revocation and unavailable policy fail closed. Commit authorization rejects a delegation identity changed after durable INTENT. Approval rechecks the original delegation identity, audience and operation, and rejects stale Ontology/rule/workflow/policy versions. AI tool proposals revalidate authorized evidence ID/revision/digest and never mutate Object state. No model service is adopted or required.

The PostgreSQL adapter keeps Object, Action, history, Outbox and successful Audit updates in one transaction, performs expected-revision checks, retries bounded serialization/deadlock failures and classifies commit transport failure as unknown. Action-key/canonical-input equality returns the original Action; changed input rejects. Audit is an append-only hash chain; the application principal cannot update/delete it. Projection consumption commits Inbox and projection atomically but never labels external ERP delivery complete.

## Independent ERP and unknown outcomes

`src/writeback.mjs` exposes authorized dispatch/reconcile through the same Kernel and generated HTTP client. A durable lease/SENDING state precedes outbound HTTP. Policy, worker scope, original actor/subject/delegation and journal state are rechecked before delivery. Payloads contain original Action/operation IDs, tenant/store, sequence and typed fields; secret Object columns are omitted. External contract 1.0.0 uses a fixed per-Action scalar allowlist in Writeback.payload; the full internal Object/Outbox snapshot is never serialized to ERP. Unsupported contracts/actions and malformed exported fields fail closed before leasing or HTTP. Dispatch and reconcile project the same immutable event, independent of live Ontology publication; see docs/DEMO_SCENARIOS.md for the field contract. ERP uses a separate database and database principal, with a ledger/effect transaction, operation-ID digest equality and sequence-gap detection. Application-principal access to the ERP database is denied. This remains a synthetic reference adapter sharing the isolated PostgreSQL server, not a separate server failure domain.

Known acknowledgement produces DELIVERED/SUCCEEDED; explicit rejection produces REJECTED/EXTERNAL_FAILED. Transport loss or a worker failure after external commit leaves UNKNOWN or SENDING, prevents blind resend and requires ledger reconciliation. Missing ledger remains UNKNOWN. Reverse delivery parks a gap before ordered convergence. External effects and Kernel state are distinct transactions; no external exactly-once or global atomicity is claimed.

Legacy approvalActor records are recognized by provenance; valid user keys ending in :approval remain accepted. Replay checks the submission's canonical digest and both IDs against the database. A confirmed approval rollback preserves the previously committed pending Action; an unresolved INTENT still fences replay and dispatch.

Approval reconstructs the original actor/subject/delegation scope and column visibility from current share-locked identity rows. ## Finite profiles and later-stage obligations

Published Policy is rechecked at commit after INTENT, projection consumption and ERP delivery. These operators are intentionally finite, not a general workflow DSL or engine.

The generated history API validates row and column authorization even on empty pages, limits pages to 100, and supports afterRevision plus an inclusive asOfRevision. It returns Action-linked revisions without exposing secret columns. It contains committed Action and source revisions, including tombstones. Source checkpoints and immutable receipts are keyed by tenant/store/source, with strict expected-position checks. Finite each-unit ingestion validates quantity and link targets, quarantines bad records with an Audit and advancing cursor, permits explicitly linked corrections, and records transform/quality versions and valid/recorded timestamps. Descriptive source updates preserve Action-owned isolation. Repeated positions compare input digests; source collisions, gaps and unsupported units reject. Object/history/links/receipt/checkpoint/Audit commit together, with injected rollback after Object and checkpoint writes. The synthetic snapshot profile is an immutable change-log prefix through a declared barrier. A versioned pipeline accepts that prefix plus changes; overlapping positions must have identical digests, gaps and rewrites reject. Job cursor, source receipt/checkpoint, Object/history/link and Audit commit together. Dependencies must have succeeded; immutable job input digest, cancellation and actor/subject/delegation binding survive restart. Tests SIGKILL an actual worker before and after checkpoint commit, reopen its persisted job and assert no duplicate history or missing cursor. This bounded fixture connector is not a general external CDC connector; plans contain at most 100 entries and ten dependencies.

Retention tests advance only the application Date clock to 30 days minus/plus one second, exactly 30 days and 18 years, reopen Kernel/journal over retained real PostgreSQL rows and replay through independent ERP HTTP. ## Caller deadlines and cancellation — B-FINAL-002

`src/budget.mjs` creates a finite absolute budget once at the public boundary. Gateway authentication, Kernel entry points, admission waits, StatePort transactions/retries, schedule effects, secret resolution, WritebackPort apply/status, and continuity recovery/compensation receive that same deadline and signal. Default five seconds and maximum thirty seconds are unchanged; waiting does not grant a new budget. HTTP request abortion or an unfinished response closing cancels the operation.

The PostgreSQL adapter bounds pool checkout, polls the admission lock with the remaining budget, sets each SQL statement/lock timeout to the remaining time and cancels its own active backend on abort. Before COMMIT begins it checks the budget; confirmed rollback permits the journal ABORTED marker and safe same-key retry. Once COMMIT starts, cancellation does not pretend to undo a potentially committed transaction. Postcommit journal markers, denial Audit and telemetry are independent consistency/diagnostic cleanup, not a renewed caller budget for further delivery or recovery work.

Writeback carries the original budget through token/secret resolution and ERP fetch. After the send lease or SEND_STARTED marker is durable, an expired/cancelled request does not manufacture a failure acknowledgement: SENDING and the durable operation identity remain available to a new reconciliation request. A new request has its own budget and resolves the ERP ledger without duplicate effects. Recovery classification and compensation use the caller budget, including their nested Kernel calls.

`deadlines-foundation` runs nineteen assertions in `tests/foundation/deadlines.test.mjs`: expired/cancelled public dispatch, reconciliation, continuity, recovery and compensation; HTTP admission wait without a fresh budget; cancellation/expiry after a lease but before HTTP; actual in-flight ERP application; HTTP client disconnect; cancellation during recovery ledger lookup; SQL lock cancellation with confirmed rollback and same-key retry; and the remaining public Kernel operations. Actual PostgreSQL/ERP HTTP state, Action/Outbox/history/journal and fresh reconciliation are asserted. Abort hooks control interleavings and do not replace business persistence or transport with mocks. The initial eleven failing regressions are retained in evidence/FAILURES.md. Separate-session review remains required.


## Authority expiry across SQL waits — B-FOUNDATION-007

Authentication no longer captures a timestamp before its SQL reads. Each authenticated session and delegation registers its absolute expiry with the transaction, including the original delegation during approval. The earliest registered expiry is checked against the current wall clock when registered, before and after every later SQL operation, and immediately before COMMIT starts. SHARE locks preserve identity/revocation state; they do not preserve time validity. A request deadline does not extend session or delegation authority. A detected expiry returns PERMISSION_DENIED and rolls back business writes. COMMIT already started is not retroactively declared undone; denial Audit and confirmed-rollback journal records remain diagnostic cleanup.

The eight-case authentication-expiry-foundation suite uses actual PostgreSQL blockers and HTTP requests. It covers session/delegation expiry during initial authentication, execution reauthorization waiting for Policy or Object locks, expiry after business writes, original delegation expiry during approval, and expiry after the last SQL statement but before COMMIT. Rejections preserve Object/Action/history/Outbox state and denial Audit; renewed credentials allow same-key retry without duplicate effects. Trusted hooks control ordering only. Four initial regressions failed before the repair; their TAP remains in evidence/generated/foundation/failures/authentication-expiry-before-20261012.tap. The transaction detects expiry after a SQL wait returns; the caller budget still bounds the wait. This repair requires independent review, and shared-code demo/BCP/release receipts must be regenerated.


## Worker original delegation expiry — B-FOUNDATION-008

Kernel.consume and Writeback.checked now register the saved Action's original delegation expiry with requireAuthorityUntil after validating that delegation. The transaction retains the earliest authority expiry, including the worker session, and checks current time after SQL waits and immediately before COMMIT. A valid worker session cannot extend the original delegation. Existing revocation, scope and definition checks remain in place.

The seven-case worker-authority-expiry-foundation suite uses real PostgreSQL and ERP HTTP. Three regressions failed before the repair: expiry after Inbox writes, after ERP apply, and during an actual blocked ERP ledger read. Four additional cases cover already-expired authority at consume/dispatch/reconcile and valid delegated consumption/delivery with deduplication. HTTP submission creates the saved Action; consume runs through Kernel and the real database, while dispatch/reconcile use the HTTP gateway. Hooks only control transaction ordering.

Expired authority rolls back Inbox/projection/Consumed Audit or local delivery completion and records denial Audit. An already committed original submission remains COMMITTED, without an ABORTED record. If ERP has applied the operation, the previously durable SENDING/UNKNOWN state and operation identity remain; renewal followed by a new reconciliation resolves the single external effect without retransmission. This does not claim rollback of ERP effects or exactly-once transport. The caller deadline bounds SQL waits; authority expiry is checked when the wait returns, without an additional expiry timer.
